# 流程覆盖度初判：Nexus PRD vs Sub2API

**编制日期**：2026-05-07
**依据**：Nexus PRD v1.9 + Sub2API 源码模块速查

---

## 1. 覆盖度判定标准

| 符号 | 含义 |
|------|------|
| ✅ 完全覆盖 | Sub2API 完整实现 Nexus PRD 描述的流程 |
| ⚠️ 部分覆盖 | Sub2API 有实现但与 Nexus PRD 存在差异，需改造 |
| ❌ 缺失 | Sub2API 无对应实现，需新增 |
| — | 与 Nexus PRD 无关或不适用的模块 |

## 3. 差异详情

### 3.1 ⚠️ 差异 #1：订阅粒度不同（流程 #5, #8）

| 维度 | Nexus PRD | Sub2API 现状 |
|------|----------|-------------|
| 订阅粒度 | **按 Provider**（每用户每供应商独立订阅实例） | **按 Group**（订阅绑定到分组，用户通过分组继承订阅） |
| tokens.subscription_id | 指向 `provider_quota_usage.id`（订阅实例） | 指向 `user_subscriptions.id`（用户订阅记录） |
| 订阅实例概念 | 有（status=0/1/2 三态） | 无（user_subscriptions 只有激活态） |
| 多订阅并存 | 同 Provider 可有多状态订阅记录 | 同 Group 同一时刻只有一条激活记录 |

**影响**：Nexus 的"订阅实例"是每用户每 Provider 独立维护的，Sub2API 缺少这一层抽象。

---

### 3.2 ⚠️ 差异 #2：渠道概念不同（流程 #7）

| 维度 | Nexus PRD | Sub2API 现状 |
|------|----------|-------------|
| 渠道定义 | API Key + Base URL 的接入点 | 账号（Account）即渠道 |
| 数据库表 | `channels` 表（独立） | 账号即渠道，`accounts` 表 |
| channels.group | 渠道归属分组标签 | **缺失** |
| allowed_channels | 分组可用渠道ID列表 | **缺失** |
| abilities | 分组→供应商权限映射 | **缺失** |

**影响**：`channel_handler.go` 实际管理的是 `channel_monitors`（监控配置），与 Nexus 定义的"渠道"不是同一概念。

---

### 3.3 ⚠️ 差异 #3：计费模型不同（流程 #5）

| 维度 | Nexus PRD | Sub2API 现状 |
|------|----------|-------------|
| 计费公式 | `Token数 × 渠道基础单价 × 渠道倍率 × 分组倍率` | 分散在 `usage_logs` 各字段 |
| model_pricing 表 | 有（平台级模型定价） | **缺失** |
| 预估费用 | input 精确，output 取 max_tokens 上限 | 直接按实际 output 计费 |
| 熔断机制 | 有（连续3次失败触发，30秒探测，180秒超时） | **缺失**（无独立熔断逻辑） |

**影响**：Nexus 计费有完整的单价体系和熔断保护，Sub2API 缺少这些。

---

### 3.4 ⚠️ 差异 #4：abilities 权限映射缺失（流程 #10, #7）

| 维度 | Nexus PRD | Sub2API 现状 |
|------|----------|-------------|
| abilities 表 | 分组→供应商权限映射 | **缺失** |
| allowed_channels | 分组可用渠道ID列表 | **缺失** |

**影响**：Sub2API 的账号→分组关联是纯碎的分组归属，无权限层级校验。

---

## 4. 缺失功能汇总

| # | 缺失项 | 对应 Nexus 流程 | 优先级 |
|---|-------|---------------|--------|
| 1 | `channels` 表（独立渠道表） | #7 渠道管理 | P0 |
| 2 | `providers` 表（供应商配置） | #5 API调用计费 | P0 |
| 3 | `model_pricing` 表（模型定价） | #5 API调用计费 | P1 |
| 4 | `abilities` 表（分组→供应商权限） | #10 分组管理 | P1 |
| 5 | `allowed_channels`（分组可用渠道范围） | #10 分组管理 | P1 |

| 7 | 熔断机制（连续3次失败+探测+恢复） | #5 API调用计费 | P2 |
